# ADR-0006：v0.1 主通道改用 PTY（交互式 TUI）

- 状态：已被 [ADR-0007](./0007-structured-chat-pty-terminal.md) 取代（Superseded）
- 日期：2026-07-31
- 关联：[ADR-0001](./0001-v0.1-oneshot-resume-model.md)（本决策在"通道"维度上修订它）、[PLAN-v0.1](../PLAN-v0.1.md)

> 本 ADR 记录 2026-07-31 的阶段性 PTY-first 决策。对 open-design
> 的生产实现完成源码调研后，默认编排通道已改回结构化 stdio；PTY
> 仅保留给显式 Terminal 接管。现行决策见 ADR-0007。

## 背景（Context）

ADR-0001 选了模型一（结构化 stream-json 一击 + resume）。实测体验差，三个固有痛点：

1. **不流式**——`-p --output-format stream-json` 默认不带 partial，整轮结束才出一个完整 assistant 事件（干等后答案一次性蹦出）。
2. **每条冷启动**——每条消息重 spawn 进程 + 模型冷读。
3. **UI 像日志**——事件卡片不如 agent 原生 TUI。

## 决策（Decision）

v0.1 主通道改为 **PTY（`node-pty` + `xterm.js`）跑各 agent 的原生交互式 TUI**：

- 每 agent 一个**常驻** PTY，跑在隔离 worktree（[ADR-0002](./0002-per-agent-git-worktree.md)），带各自自治 flag（claude `--dangerously-skip-permissions` / kimi `--yolo` / codex）。
- follow-up = 往同一 PTY 写字 = 模型二 §4.1 的"同进程连续对话"，只是走 PTY 通道 → **无冷启动、原生流式、原生 TUI**。
- `@@` 路由（[ADR-0004](./0004-at-at-explicit-routing.md)）= 往目标 agent 的 PTY 写 `text\r`；`@@all` = 写三家。也支持直接在终端打字。
- 副效果：codex/kimi 不再需要 per-agent decoder，交互式 TUI 立刻可用。

## 后果（Consequences）

- **正面**：流式、暖进程、富 TUI、即时 follow-up——三个原痛点全解；codex/kimi 即时接入。
- **负面**：失去结构化事件 → 回合边界 / usage / session-id 只能从终端 bytes **推断**（不可靠）；"3 家对比"降级为视觉并排；`@@` 为字节注入（程序无法证明 agent 消费）。
- **保留**：结构化 adapter / decoder / run-manager / session-store 代码（已测）作为未来 [ADR-0005](./0005-future-duplex-upgrade.md) 模型二双向或元数据旁路的复用基础，**不在当前主流程**。
- **构建**：`node-pty` 是原生模块，须用 `npm run rebuild:native`（electron-rebuild）按 Electron ABI 编译。
