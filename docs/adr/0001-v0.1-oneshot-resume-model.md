# ADR-0001：v0.1 采用模型一（一次性 exec + 原生 resume）

- 状态：已接受；会话连续性细节由 [ADR-0007](./0007-structured-chat-pty-terminal.md) 修订
- 日期：2026-07-31
- 关联：[PLAN-v0.1](../PLAN-v0.1.md)、[agent-adapter-architecture §4/§12](../../agent-adapter-architecture.md)、[ADR-0005](./0005-future-duplex-upgrade.md)

## 背景（Context）

方案 B（结构化优先）下，会话模型有两条路：

- **模型一**：每条 `@@` 消息 = 一次 `-p`/`exec` 结构化调用，进程跑完即退出；对话延续靠 `--resume <nativeSessionId>`。
- **模型二**：每 agent 常驻一个双向协议进程（Claude stream-json / Kimi ACP / Codex app-server），follow-up 走 stdin。

三家双向协议成熟度严重不齐：Claude 生产级、Kimi ACP 开放标准、Codex `app-server` 仍是 experimental。模型二需实现 3 套不同的双向驱动 + 长驻进程生命周期。

## 决策（Decision）

v0.1 **统一用模型一**。每条消息 spawn 一个非交互进程、读结构化 stdout，
进程完成即退出。Claude/Codex 捕获 nativeSessionId 并以 `--resume` 续接；
Kimi 当前在单次进程内使用 ACP JSON-RPC、跨进程以 bounded transcript 续接
（见 ADR-0007）。**不保留跨 turn 常驻 agent 进程。**

## 后果（Consequences）

- **正面**：唯一能在三家 agent 上统一的模型；复杂度断崖式下降（无 duplex 驱动、无长驻进程管理）；天然契合 `@@all` 广播（并发起 3 个独立 run）。
- **负面 / 代价**：每条消息有冷启动开销；依赖各家 `--resume` 可靠性（Kimi / Codex 需 probe 验证）；不支持 mid-run steer / 中断（"停止" = kill 进程）。
- **演进**：模型二留作未来升级，见 [ADR-0005](./0005-future-duplex-upgrade.md)，按 Claude → Kimi → Codex 顺序逐 adapter 上 duplex。
